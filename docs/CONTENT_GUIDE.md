# 內容撰寫與維護指南

本文件說明「臺北市立大學生成式 AI 與 AI Agent 自主學習平台」所有教材、影片與 Prompt 的撰寫規範。新增或修改內容前請先閱讀。資料型別定義在 `src/content/types.ts`。

## 一、語言與語氣

- 一律使用**繁體中文（臺灣用語）**：例如「資訊、軟體、程式、網路、影片、檔案、介面、使用者、預設、設定、儲存、列印、品質、文件、資料庫、專案」，避免「信息、軟件、程序、網絡、視頻、文檔、用戶、默認、質量、數據庫、項目」等用語。
- 對象為臺北市立大學的大學生與研究生，語氣專業、清楚、友善，不說教、不誇大。
- 中英文之間保留半形空格（例如「使用 ChatGPT 時」）。

## 二、正確性原則（強制）

1. **不得編造**工具入口、按鈕名稱、免費額度、付費方案、模型名稱排名或功能限制。
2. 介面說明要寫成「可能因帳號方案、地區、版本與更新而不同」，用「通常」「多數版本」「若你的介面有……」等措辭；描述位置時以功能為主（例如「附件入口（常見為迴紋針或＋號圖示）」）。
3. 不宣稱任何模型在所有任務中最強。
4. 不得產生假 DOI、假論文、假政策、假統計、假校內資訊。需要範例文獻時使用明確的佔位符，例如 `[作者，年份]`。
5. AI 回答不等於已查核的來源；所有涉及事實、數據、文獻的內容都要提醒查核原始來源。
6. **Gem 是保存固定指示（與可選的參考檔案）的自訂版 Gemini，不是重新訓練模型**，不可寫成「訓練你自己的模型」。
7. Deep Research、Canvas、Gem、ChatGPT 的搜尋、語音、專案（Projects）、自訂指令／個人化、記憶等功能，是否可用取決於方案與地區，提到時都要附帶這個提醒。
8. 校內 AI 伺服器、計中單位資訊、聯絡方式、申請辦法等**一律標註「待計中確認」**，不得自行填寫規格、網址、GPU 型號、帳號權限或服務名稱。

## 三、內容來源標示

每個教材段落（`LessonSection`）都有 `origin`：

- `script`：**影片腳本既有內容**。目前正式腳本檔 `生成式ai使用教學影片.docx` 尚未放進專案，因此 `script` 段落是依「開發指令中列出的影片大綱」撰寫，頁面會標示「依影片規劃大綱｜腳本全文待核對」。只能寫大綱中列出的主題，不可把延伸內容放進 `script`。
- `extension`：**網站新增的延伸教材**，頁面會標示「網站延伸教材」。背景概念、情境應用、進階技巧、FAQ、倫理提醒等都屬此類。

取得腳本後，請逐段核對 `script` 段落並更新 `sourceReference`。

## 四、既定影片（不得更改編號）

### ChatGPT 網頁版（A 系列）
- **A01｜認識 ChatGPT：介面與基本功能**：頁面及主要操作介面、新對話與歷史紀錄、輸入區與附件入口、模型與回答設定、搜尋與語音入口、第一次提問、設定與使用偏好、基本操作練習。
- **A02｜學會提問：讓回答更符合需求**：如何說明任務、補充背景與需求、指定回答格式、追問與修正、資訊不足時先釐清、何時建立新對話、提問技巧與練習。
- **A03｜使用資料與搜尋：從回答到查核**：貼上文字與說明任務、上傳文件、確認文件是否正確讀取、摘要與原文對照、圖表理解、搜尋補充資料、來源查核、資料處理與查核練習。

### Gemini 網頁版（B 系列）
- **B01｜認識頁面、選擇模式與第一次提問**：Gemini 頁面操作、新對話與歷史紀錄、輸入區與工具入口、Gem 與設定入口、模型或模式選擇、第一次提問、追問調整、管理對話。
- **B02｜使用文件、Canvas 與 Deep Research**：加入與整理文件、文件讀取確認、Canvas 的用途與操作、建立及修改內容、Deep Research 的研究用途、研究計畫的確認、閱讀報告與查核資料來源。
- **B03｜建立與使用自己的 Gem**：Gem 的用途、建立 Gem、設定名稱與固定需求、區分固定指示和當次任務、測試與修改、儲存與再次使用、更新後重新確認、實際練習。

### 共通課程（C 系列）
- **C01｜AI 素養：理解工具，判斷回答**：生成式 AI 如何產生回答、AI 的能力與限制、幻覺與不確定資訊、資訊查核、偏誤與遺漏觀點、資料與隱私、保留自己的思考與判斷。
- **C02｜學術倫理：在學習與作業中負責使用 AI**：課程與作業使用規範、AI 協助與代做的差異、抄襲、改寫及原創性、不得捏造資料、文獻或過程、原始來源引用、AI 使用揭露、保留工作過程、提交成果前的責任與檢查。

## 五、ID 規則

| 類型 | 格式 | 範例 |
|---|---|---|
| 影片 | 正式單元編號 | `A01`、`B03`、`C02` |
| ChatGPT 教材 | `chatgpt-a0N` | `chatgpt-a02` |
| Gemini 教材 | `gemini-b0N` | `gemini-b02` |
| 共通課程 | `literacy-c0N` | `literacy-c01` |
| AI Agent 自主學習與專題實作 | `agent-l01`～`agent-l10` | `agent-l03` |
| AI Agent 學術研究 | `research-r01`～`research-r12` | `research-r05` |
| Prompt | 既有 ID 不變；新增沿用所在檔案的前綴與流水號 | `research-37`、`lit-13`、`teach-17` |

Prompt 分類（`category`）：`study` 自主學習、讀書計畫與考試準備、`slides` 簡報設計、PPT 與口頭報告、`image` AI 圖片生成與視覺設計、`video` 影片企劃、腳本、分鏡與剪輯、`research` 學術研究與論文寫作、`literature` 文獻檢索、文獻回顧與引用、`methods` 研究方法與研究設計、`data` 統計分析、資料處理與視覺化、`writing` 文字撰寫、校對與改寫、`english` 英文學習、翻譯與語言應用、`code` 程式設計、網站與 App 開發、`agent` AI Agent、任務自動化與工作流程、`teaching` 教育教學、課程與教材設計、`audio` 聲音製作、配音與逐字稿、`admin` 行政文書與工作效率、`career` 履歷、面試與職涯規劃、`creative` 創意發想、行銷與社群內容、`ethics` AI 素養、資訊查核與學術倫理。

子分類（`subcategory`）請沿用該分類現有名稱，每個分類維持在 10 個以內，方便篩選。

教材與 Prompt 的關聯只需寫在 Prompt 的 `relatedLessonIds`；教材頁會自動反查，若教材想額外指定，也可寫在 `relatedPromptIds`。

## 六、Prompt 撰寫標準

- 完整的任務描述：角色（可選）、任務、背景、輸入資料、限制、輸出格式、資訊不足時先提問。
- 變數一律用方括號，例如 `[主題]`、`[對象]`、`[字數]`；變數名稱要讓人看得懂該填什麼。
- 每則 Prompt 的邏輯要針對任務設計，不可只換標題重複套版。
- 研究類 Prompt 一定要包含：不得編造文獻、DOI、數據或研究結果；請標示不確定處；文獻須自行查核；不得上傳個資或未經許可的研究資料。
- 不得產生鼓勵抄襲、代寫作業、捏造資料或規避學術倫理的 Prompt。
- `supportedTools` 只標實際可行的工具；需要特定功能（例如 Deep Research、Gem、圖片生成）時要在 `caution` 說明「需你的方案支援該功能」。

## 七、結構化 Prompt 表單

`PromptItem.form` 為選填的 `PromptFormField[]`；未設定者沿用一般占位符輸入。各欄包含 `group`（分組）、`label`（顯示名稱）、`placeholder`（精確對應正文的方括號內名稱，不含括號）、`type`。支援 `text`、`number`、`textarea`、`select`、`multiselect`；選項型另提供 `options: string[]`。

每個正文占位符都應對應一欄，欄名不可重複；單選提供留空選項，多選以「、」依選項順序串接。所有欄位皆非必填，空白維持原占位符。核心 `teach-core` 包含基本資料、學生與環境、課程依據與策略三組；完整正文以交接文件為準，勿摘要或裁切 18 項要求及 A–J 輸出。複製以完整字串為準，不得從視覺卡片摘要取值。

教案內容須提醒教師核對課綱、教材及生成結果，禁止上傳學生個資，不得編造課綱代碼、文獻或教學成效。尚未實施的課程只寫預期觀察與省思。

桌面版教材軌道 `chatgpt-desktop`、`gemini-desktop` 目前保持空白，待內容確定再依既有 Lesson 型別新增。
